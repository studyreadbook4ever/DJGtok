# DJGtok — 대중교통 토큰화

서로 다른 노선도 일정 구간에서는 같은 방향으로 함께 움직입니다. **이 움직임을 재사용 가능한 표현으로 만들고, 실제로 어디부터 어디까지 겹치는지 설명하자**는 생각에서 출발한 Python 라이브러리입니다.

[English README](README.md) · [구조](docs/architecture.md) · [실측 결과](docs/benchmarks.md) · [사용법](docs/usage.md) · [개발 과정](docs/history.md)

## 지금 제공하는 것

* `TransitTokenizer`: 정류장 사이의 이동을 여러 크기의 공간 토큰과 방향·거리·교통수단 등의 연속 특성으로 표현합니다. 기본 출력은 구간마다 토큰 3개와 수치 특성 42개입니다.
* `compare_routes`, `OverlapIndex`: **같은 정류장 ID·같은 방향·같은 교통수단**이 연속되는 가장 긴 구간을 찾습니다. 몇 개 구간이 겹치는지, 두 노선에서 어느 정류장 범위인지 함께 반환합니다.
* 사용자가 직접 확보한 GTFS와 서울 버스 정류소 XLSX를 읽는 어댑터, 합성 예제, 실험 재현용 코드가 있습니다.

길찾기 서비스가 만든 경로들을 비교하거나, 공통 구간을 설명하는 데 붙일 수 있습니다. 시간표 기반 최적 길찾기·실시간 도착 예측·환승 가능성 판정까지 구현한 것은 아닙니다. 정류장 사이의 실제 도로 경로가 같다는 보장도 하지 않습니다.

## 설치

Python 3.11–3.13에서 사용합니다. PyPI에는 올리지 않았으며 GitHub에서 설치합니다.

```sh
python -m pip install "git+https://github.com/studyreadbook4ever/DJGtok.git@v0.1.0"
djgtok demo
```

예제는 직접 만든 가상 데이터라 교통 데이터나 모델 다운로드가 필요 없습니다. [영문 README](README.md)의 짧은 코드와 [사용법](docs/usage.md)에서 시작할 수 있습니다. 서울 엑셀은 `seoul`, 신경망 연구 코드는 `torch` 선택 의존성으로 분리했습니다.

## 실패한 실험도 공개합니다

예전 신경망 검색에서는 72개 구간을 공유하는 노선이 27위에 나왔습니다. 작은 구간의 코사인 유사도만 크게 나와도 높은 점수를 받는 방식이, **함께 움직이는 구간의 길이**라는 목적과 맞지 않았습니다. 이를 기본 검색에서 제외했습니다.

현재 기본 검색은 연속된 실제 정류장 ID 일치를 계산합니다. 정류장 ID를 모르는 관측 궤적의 유사성을 학습해서 해결했다는 뜻은 아닙니다. 신경망은 `experimental`에 연구용으로 남겨두었으며, 원본 데이터와 학습 가중치는 배포하지 않습니다. 지표의 분모·실험 조건·제약은 [벤치마크 문서](docs/benchmarks.md)에 있습니다.

서울시 OA-1095의 2026-09-02 자료에서 유효한 707개 버스 패턴, 정류장 등장 40,883건을 확인했습니다. 순번이 누락된 11개 노선은 임의로 연결하지 않고 제외했습니다. 공개물에는 집계 지표와 실행 코드만 포함하며, 서울시 자료는 [공식 페이지](https://data.seoul.go.kr/dataList/OA-1095/L/1/datasetView.do)의 별도 이용 조건과 출처 표시를 따릅니다.
